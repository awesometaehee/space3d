# 일정 조율

참석자들의 공통 빈 시간을 찾고, 회의실을 잡고, 초대를 보내는 흐름입니다. 회의실 예약을 "사람 기준"으로 넓힌 업무입니다.

## 흐름

```
"다음 주 기획팀이랑 1시간 회의 잡아줘"
  → (참석자를 못 읽었으면) pick_attendees   조직도에서 참석자 고르기
  → show_common_times    추천 시간 + 날짜×30분 가능 인원 히트맵   [참석자 바꾸기] [취소]
  → pick_meeting_room    그 시간에 비어 있고 인원이 들어가는 방 + "회의실 없이 진행"   [다른 시간] [취소]
  → confirm_invite       제목·메모 수정, 참석자 확인 후 [초대 보내기] [취소]
  → 일정 등록 + 회의실 예약 (백엔드) → STATE_DELTA로 schedule.events, meetingRoom.bookings 추가
  → show_invite_result   완료 카드 (참석자별 "응답 대기", 보여 주기만)
```

## 요청 해석 (모의)

| 항목 | 표현 | 기본값 |
|---|---|---|
| 참석자 | 팀 이름("기획팀", "우리 팀"), 사람 이름("한결님", "아름 수석이랑") | 없으면 참석자 카드부터 |
| 기간 | "다음 주", "이번 주", "목요일", "다음 주 화요일", 내일·모레·"11월 20일" | 내일부터 평일 5일 |
| 시간대 | 오전 / 오후 | 하루 전체 |
| 길이 | "1시간", "30분" (30분 단위, 30분~4시간) | 1시간 |
| 제목 | 킥오프·리뷰·회고·주간·워크숍 등 + 팀 이름 | "○○팀 업무 협의" |

- 이름은 낱말 안에 들어 있으면 사람으로 보지 않는다 ("아름다운", "한결같이").
- 사람·팀과 함께 회의를 잡는 말은 회의실 예약(0.8)보다 일정 조율(0.9)이 맡는다. "회의실"만 말하면 회의실 예약이다.
- 조율 중에 "오전으로 30분만"처럼 조건만 말하면 참석자는 그대로 두고 다시 찾는다.

## 추천 후보

- 내가 안 되는 시간은 뺀다. 빠지는 사람이 적은 순 → 이른 날짜·시간 순.
- 빠져도 되는 사람은 참석자의 1/3까지 (최소 1명). 그런 후보는 "○○ 불참"으로 표시한다.
- 최대 6개, 하루 2개까지, 같은 날 겹치는 시간은 건너뛴다.
- 점심(12~13시)과 이미 지난 시간은 뺀다.

## 화면 배치

단계마다 레이아웃이 바뀐다 (`DomainUI.spatial` → 공유 상태 `schedule.stage`).

| 단계 | 패널 | 복셀 |
|---|---|---|
| 참석자·시간 찾기 | 넓게 (히트맵이 폭을 쓴다) | 전체 줌 아웃 |
| 회의실 고르기 | 좁게 | 쓸 수 있는 방 강조·확대, 3D에서 눌러도 선택 |
| 초대 확인 (회의실 있음) | 좁게 | 고른 방 강조 |
| 완료 | 넓게 | 예약한 방에 초록 이름표 |

## 다루는 정보

- 조직도는 **업무 연락처 수준**(이름·팀·직급)만 둔다.
- 다른 사람의 일정은 **바쁨/비어 있음만** 보여 준다. 제목·장소·사유는 다루지 않는다.
- 초대는 사용자가 [초대 보내기]를 눌러야만 나간다. 에이전트가 혼자 보내지 않는다.
- PoC에서는 실제로 보내지 않고 가상 일정 저장소(`src/data/calendar.ts`)에만 기록한다.

## 가상 데이터

| 팀 | 사람 |
|---|---|
| 플랫폼팀 (내 팀) | 복셀 재실 목록의 12명과 같다 |
| 기획팀 | 한결 책임, 소망 선임, 하늘 매니저 |
| 디자인팀 | 아름 수석, 초롱 선임, 나래 매니저 |
| 영업지원팀 | 든솔 책임, 세찬 매니저 |

기존 일정은 사람·날짜마다 항상 같은 결과가 나오는 가상 값이다.
