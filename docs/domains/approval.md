# 전자결재

결재함 조회·처리는 **고정 작업 화면**, 기안은 **대화 카드**로 한다. 에이전트는 공유 상태로 결재함 화면을 조작하고, 판단을 돕는다.
승인·반려·상신은 **항상 사람이 버튼으로** 확정한다.

코드: `src/agent/domains/approval/`, 가상 데이터·저장소: `src/data/approvals.ts`

## 왜 결재함은 고정 화면인가

- 단순 조회에 매번 에이전트(LLM)를 거치면 느리고, 비용이 들고, 결과가 달라질 수 있다.
- 실제 결재함은 문서가 많아 검색·필터·정렬·탭이 필요하다. 대화 흐름에는 맞지 않는다.
- 결재는 같은 화면이 같은 자리에 있어야 실수가 줄고, 에이전트가 멈춰도 업무가 돼야 한다.

그래서 **화면이 기본 업무(조회·처리)**, **에이전트가 조작·해석(필터, 요약, 의견 초안, 기안)** 을 맡는다.

## 화면 구성

하단 바 "결재 대기 N"을 누르면 **에이전트를 거치지 않고** 바로 열린다. 패널은 왼쪽 작업 화면 + 오른쪽 대화 열로 나뉘고 (화면의 70%, 720~1180px), 복셀은 남은 왼쪽에 줌 아웃된다.

| 영역 | 내용 |
|---|---|
| 탭 | 결재할 문서 / 처리한 문서 / 내가 올린 문서 (건수 표시) |
| 도구 줄 | 검색(제목·기안자·문서 번호), 전체·긴급·확인 필요, 양식, 정렬(긴급·오래된 순 / 금액 큰 순 / 최근 순), 조건 지우기 |
| 목록 | 양식·긴급 표시, 제목, 기안자·날짜·문서 번호, 금액, 확인 메모 수 |
| 상세 | 금액, 내용, 첨부, 결재선 / 에이전트 확인 메모, 의견 → [반려] [승인] → 한 번 더 확인 → 확정 |
| 처리 후 | 잠깐 알림("…를 승인했어요. 남은 문서 N건"), 목록·탭 건수·하단 바 숫자가 바로 바뀜 |

## 에이전트와 화면의 연결 (공유 상태)

```ts
approval.view = {
  open, tab,                      // 화면을 열었는지, 어느 탭인지
  query, form, only, sort,        // 검색·양식·긴급/확인 필요·정렬
  selectedId,                     // 상세를 연 문서
  commentDraft: { docId, text },  // 에이전트가 넣어 준 의견 초안
}
```

- **화면 → 에이전트**: 사용자가 화면에서 문서를 열거나 필터를 바꾸면 공유 상태가 바뀌고, 다음 실행 때 에이전트가 받는다. 그래서 "이 문서 요약해줘"의 "이 문서"를 안다.
- **에이전트 → 화면**: 에이전트가 `STATE_DELTA`로 `/approval/view`를 바꾸면 화면이 그대로 따라 움직인다.
- 업무 데이터(문서 목록 등)는 공유 상태에 두지 않는다. 화면과 에이전트가 같은 저장소(그룹웨어 API 자리)를 읽는다. 저장소는 바뀌면 구독자에게 알린다.

## 에이전트에게 할 수 있는 말

| 요청 | 에이전트가 하는 일 |
|---|---|
| "결재할 거 보여줘", "결재함 열어줘" | 결재함을 열고 건수·긴급 건수를 알려 줌 |
| "확인이 필요한 것만", "긴급한 것만", "휴가신청만" | 필터를 걸고 건수를 알려 줌 |
| "금액 큰 순으로", "최근 순으로" | 정렬을 바꿈 |
| "단비가 올린 거" | 기안자로 검색 |
| "모니터 결재 열어줘" | 그 문서 상세를 엶 |
| "이 문서 요약해줘" | 열어 둔 문서를 요약 (확인 메모 포함, "최종 판단은 직접") |
| "반려 사유 써줘", "승인 의견 써줘" | 의견 칸에 초안을 넣음 ("에이전트 초안" 표시). 사용자가 고쳐서 버튼으로 확정 |
| "이거 승인해줘" | **확정하지 않는다.** 문서를 열어 두고 버튼으로 확정하라고 안내 |
| "다 승인해줘" | **일괄 처리하지 않는다.** 결재함을 열고 하나씩 확인하라고 안내 |
| "처리한 문서", "내가 올린 문서" | 해당 탭으로 이동 |
| "어제 택시비 23,000원 지출결의 올려줘" | 기안 초안 카드 (아래) |

결재함이 열려 있으면 "결재"라는 말이 없어도 이어지는 말("긴급한 것만", "요약해줘")을 결재 요청으로 알아듣는다.

## 기안 (대화 카드)

```
"어제 택시비 23,000원 지출결의 올려줘"
  → show_approval_draft   초안 폼: 양식, 제목, 금액, 사용일, 결제 수단, 내용, 결재선
                          읽지 못한 칸은 비워 두고 강조. 다 채워야 [상신] 활성 → 한 번 더 확인
  → 상신 (저장소) → 결재함 "내가 올린 문서"에 쌓임
  → show_draft_result     문서 번호, 결재선 (보여 주기만)
```

기안 초안에서 읽는 값:

| 칸 | 표현 | 기본값 |
|---|---|---|
| 양식 | "구매", "사줘", "주문" → 구매요청 | 지출결의 |
| 금액 | "23,000원", "2만 3천원", "5만원" | 비움 |
| 사용일 | 오늘·어제·그제, "11월 14일", "14일" (지난 날짜 기준) | 오늘 |
| 결제 | "개인", "사비", "정산" → 개인 비용(정산) | 법인카드 |
| 내용·제목 | 택시·주차·교통·식대·회식·다과·도서·모니터 등 | 비움 |

## 다루지 않는 정보

- 휴가 문서는 종류·기간·대결자만 보여 주고 **사유는 다루지 않는다**.
- 결제 수단은 종류만 고른다. **카드번호·계좌번호 입력란은 없다.**
- 인사·급여·계약처럼 제한(C) 정보가 담긴 결재 양식은 범위에 넣지 않는다.
